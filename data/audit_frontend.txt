FINDING #6 [MEDIUM] — Race condition: overlapping refresh() corrupts historyData
================================================================================

  File: /home/mrc/opentrader/dashboard.py
  Lines: 1504–1570 (history tracking), 2090 (setInterval)

  Evidence:
    Line 2090:  setInterval(refresh, 2000);

    The `refresh()` function is async and takes ~N*100ms to complete (multiple
    `await fetch` calls). The interval fires every 2 seconds regardless of
    whether the previous refresh completed. Inside updateMetrics(), the
    history tracking uses a mutex-like `historyData._loaded` flag:

    Line 1512:  historyData._loaded = true;
    Line 1519:  fetch('/api/dashboard/history').then(r => r.json()).then(h => {
    Line 1524:      historyData.length = 0;          // clears everything
    Line 1546:      historyData.push(seed);          // restores latest point
    Line 1547:      updateChart();
    Line 1548:  });

    If a second refresh() call runs between lines 1512 and 1524:
    1. Call 1 sets _loaded=true, pushes seed, starts history fetch.
    2. Call 2 (2s later): _loaded is true, enters `else if` at line 1552.
       Pushes a new live data point to historyData.
    3. Call 1's `.then()` fires: `historyData.length = 0` — wipes Call 2's point!
       Then pushes `seed` (which is stale since Call 2 moved historyData[0]).

  CONSEQUENCES:
  - Under load or slow API, equity curve data points are silently dropped.
  - The chart may show gaps or inconsistent history.
  - This is a Heisenbug that worsens with API latency.

  FIX: Either (a) use a generation counter or (b) prevent overlapping
  refresh() calls with an `isRefreshing` guard, or (c) use
  `setTimeout(refresh, 2000)` chaining (calling setTimeout at the end of
  each refresh completion) instead of `setInterval`.

  CONSEQUENCES:

    browser may reload the cached (old) version, showing the stale dashboard.
  - The user would need to manually hard-refresh (Ctrl+Shift+R) to see updates.

  cache-busting technique like appending `?v=` + srv.build_ts to the URL.
