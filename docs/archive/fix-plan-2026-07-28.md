## Issue A: SCOUT Universe Bottleneck (TOP)

### Symptom
Scout selects only ~3 tickers (BTC/ETH/SOL) each cycle — the rest are invisible because all equities have the same default `$100.00` price, so the radar snapshot shows 0% change for everything.

### Root Cause
`get_prices_batch()` in `exchange/alpaca_paper.py`:
1. **yfinance rate cap too low**: 30 calls/60s → only 30 stocks get real prices per cycle
2. **INDUSTRY_MEDIAN fallback has only 45 tickers** — remaining ~466 tickers get `$100.00`
3. **Crypto tickers** (`BTC/USDT`, etc.) can't be fetched via yfinance (they're crypto pairs, not equity symbols)
4. **Cache TTL is 5 min** — real prices expire before the next full universe scan

### Fix
1. **Expand INDUSTRY_MEDIAN** to cover ALL 60+ tickers from `DEFAULT_START_PRICES` plus sector-appropriate defaults for remaining INDUSTRY_REGISTRY tickers (150+).
2. **Increase yfinance rate cap** from 30 → 100 calls per 60 seconds.
3. **Increase cache TTL** from 5 min → 10 min (keeps real prices longer).
4. **Add sector-aware fallback** function instead of hardcoded `$100.00` — returns industry-appropriate price for any ticker.

### Files
- `exchange/alpaca_paper.py`: `INDUSTRY_MEDIAN` (L34-45), `_fetch_yfinance()` (L113-130), `_cached_price()` (L94-104), `_cache_price()` (L106-111), `get_prices_batch()` (L177-221)
- `mot/tradable_universe.py`: `DEFAULT_START_PRICES` (L41-63)

### Expected Result
Scout snapshot shows 60+ differentiated prices → LLM scouts 20+ unique tickers → top20 covers multiple sectors → buy/sell signals diversify beyond crypto.

## Issue B: Signal Veto Gauntlet (HIGH)

### Symptom
Signals are generated by ADIR debate but systematically blocked by 3 sequential veto layers:

| Layer | File:Line | Condition | Effect |
|-------|-----------|-----------|--------|
| Committee warmup veto | `monitors.py:196` | `adj_conf < 0.20` | Blocks ALL signals when no accuracy history (warmup mode: `acc_mult ≈ 0.7`) |
| Confidence gate | `adir_debate.py:99,618` | `gate_threshold = 0.35` | Skips falsification when both agents agree but confidence is low → synthesizes with low evq scores |
| SL/TP blocker | `harness.py:2605` | `bear_conf < 0.6` AND `risk_conf < 0.5` | Blocks SELL on existing positions unless very high conviction |

### Fix
1. **Lower committee veto threshold** from `0.20` → `0.10` (monitors.py:196)
2. **Lower confidence gate threshold** from `0.35` → `0.25` (adir_debate.py:99)
3. **Lower SL/TP blocker threshold** from `bear_conf >= 0.6` → `bear_conf >= 0.40` (harness.py:2605)

### Files
- `mot/monitors.py`: line 196
- `mot/agents/adir_debate.py`: line 99
- `harness.py`: line 2605

### Expected Result
Signals with confidence ≥ 0.25 pass committee review (even during warmup). Lower thresholds allow bearish signals to override SL/TP guards. More trades execute → accuracy tracker accumulates data → warmup ends.

## Issue C: qwythos-9b Model Instability (HIGH)

### Symptom
qwythos-9b-mtp crashes intermittently → comes back cold → evq drops to 0.01 → takes 2-3 cycles to warm up → often crashes again before gaining conviction. Rinse and repeat.

### Root Cause
qwythos-9b runs with **524K context** on a 17GB GPU (RX 7900 GRE). Model size ~6.5GB. With 524K context, the KV cache can grow to ~10GB when fully utilized, pushing total VRAM usage to 16-17GB → OOM crash under load.

### Fix
1. **Reduce context from 524K → 256K** — halves KV cache pressure, still ample for debate prompts (~2-3K tokens each).
2. **Restart llama-server with reduced context** and monitor stability.

### Command
```bash
llama-server -m /home/mrc/.local/models/.../qwythos-9b-mtp-Q4_K_M.gguf \
  --host 127.0.0.1 --port 5802 --n-gpu-layers 99 --ctx-size 262144 --threads 8 --batch-size 2048
```

### Expected Result
KV cache ~5GB instead of ~10GB → total VRAM usage ~12GB → stable operation, no OOM crashes → evq stays above 0.30 → signals retain conviction across cycles.
